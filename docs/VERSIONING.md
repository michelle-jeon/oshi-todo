# 버저닝

OshiTodo는 작게 시작하되, 나중에 작업 흐름을 되짚을 수 있도록 간단한 시맨틱 버저닝을 사용한다.

```text
MAJOR.MINOR.PATCH
```

## 공개 전 버전 기준

- `0.1.x`: 로컬 MVP 뼈대와 초기 플레이 가능 프로토타입
- `0.2.x`: 다른 사람에게 보여줄 수 있는 웹 MVP
- `0.3.x`: 캐릭터, 옷장, 상점, 밸런스 고도화
- `0.4.x`: 데스크톱 작업 시간 추적, PWA, 모바일 실험
- `1.0.0`: 첫 공개 릴리스

## 언제 올릴지

- 패치(`PATCH`): 버그 수정, 문구 수정, 작은 UI 정리
- 마이너(`MINOR`): 캘린더, 루틴, 친구, 광장처럼 사용자가 체감하는 기능 추가
- 메이저(`MAJOR`): 공개 이후 데이터 모델이나 사용 방식이 크게 깨지는 변경

## 현재 운영 방식

- 의미 있는 기능 묶음이 끝나면 `package.json`의 `version`을 올린다.
- `CHANGELOG.md`에 무엇이 바뀌었는지 짧게 적는다.
- `docs/VERSIONING.md`에는 현재 버전과 릴리스 흐름을 남긴다.
- 커밋 메시지는 기능 단위로 남긴다.
- 나중에 중요한 지점은 `v0.2.0`처럼 Git 태그를 붙인다.

## 현재 버전

- `0.2.7`: 옷장 인벤토리 장착 흐름 추가 진행 중.

## 릴리스 기록

- `0.2.7` - 옷장에서 보유 아이템 목록을 읽고 구매한 캐릭터 아이템을 장착해 저장하는 흐름 추가.
- `0.2.6` - Turbopack 개발 서버 패닉을 피하도록 webpack 개발 모드로 고정하고, 세션 없는 보호 페이지의 인증 API 반복 호출을 차단.
- `0.2.5` - 캐릭터 목록, 생성, 옷장까지 캐릭터 레이어 이미지를 일반 이미지 렌더링으로 통일.
- `0.2.4` - 캐릭터 레이어 이미지의 Next 이미지 런타임 반복 반응과 개발 중 깜빡임 정리.
- `0.2.3` - Google 로그인 버튼 반복 초기화와 라우터 초기화 전 이동 오류 정리.
- `0.2.2` - 상점, 광장, 캐릭터 방 이동 중 인증 오류 처리 안정화와 상점 미리보기 리렌더 방지.
- `0.2.1` - 투두/루틴 낙관적 UI 실패 복구, 서버 액션 오류 표시, 백로그/버전 기록 정리.
- `0.2.0` - 다른 사람에게 보여줄 수 있는 웹 MVP 기준선.
- `0.1.0` - 로컬 MVP 뼈대와 초기 플레이 가능 프로토타입.
